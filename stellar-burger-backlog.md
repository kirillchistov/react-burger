## Краткое ревью

### Что сделано хорошо

- **Полная функциональность.** Реализованы регистрация, авторизация, DnD-конструктор, лента заказов, профиль, WebSocket — всё, что предусматривало ТЗ.
- **Структура папок** в целом читаемая: `components/`, `pages/`, `services/`, `hooks/`, `utils/` разделены по назначению.
- **TypeScript strict mode** включён, базовая типизация state и actions присутствует.
- **Protected Routes** реализованы через переиспользуемый `ProtectedRouteElement` с параметром `showWhen`.
- **Modal routing** через `location.state.background` — правильный паттерн для React Router v6.
- **WebSocket middleware** написан самостоятельно, покрывает оба канала (публичный и авторизованный).
- **Кастомные хуки** `useDispatch` / `useSelector` типизированы и экспортируются.

### Системные проблемы

#### 1. Устаревший инструментарий

Проект собирается на **Create React App** (CRA) — тулчейн, который официально не поддерживается с 2023 года. Webpack 4 внутри, медленная сборка, нет поддержки современного ESM. В 2026 году это существенный технический долг для любого портфельного проекта.

#### 2. Redux — классический, без RTK

Используется `redux` + `redux-thunk` вместо `@reduxjs/toolkit`. Это учебное ограничение курса, но в реальном коде это означает:
- 3× больше boilerplate (отдельные файлы actions/reducers/types для каждого среза)
- ручная типизация action-интерфейсов (25+ interface-объявлений только в `auth-actions.ts`)
- нет `createSlice`, `createAsyncThunk`, `createEntityAdapter`

Вывод после ревью: переход на RTK — самая высокоприоритетная рефакторинговая задача.

#### 3. Состояние authReducer захламлено

`TAuthState` содержит одновременно флаги `request/requestFailed/requestOK` (общие) и `loginApi/loginApiOK/loginApiFail`, `registerApi/registerApiOK/registerApiFail` (специфичные). Смешение двух подходов. В комментарии к коду автор сам отмечает: _«Распутать это, чтобы не было ошибочных статусов по умолчанию»_ — задача так и осталась открытой.

#### 4. Отсутствие обработки ошибок в UI

Во всех API-функциях в `catch` только `console.log`. Пользователь не видит никакого фидбека при ошибке сети, 401, 422 и т.д. Форма логина при неверном пароле просто молчит.

#### 5. refreshToken отправляет accessToken вместо refreshToken

В `api.ts`, функция `refreshToken`:
```ts
body: JSON.stringify({'token': `${getCookie('accessToken')}`})  // ← BUG
```
Должен быть `getCookie('refreshToken')`. Это функциональный баг, из-за которого рефреш токенов не работает.

#### 6. Тесты — почти пусты

`redux.test.js` полностью закомментирован с пометкой «в процессе дописывания». Из покрытия есть только файлы `*.test.ts` в reducers — но они лежат рядом с кодом, а не в `__tests__`, и неясно, запускаются ли вообще.

#### 7. Проблемы в `constants.ts`

- `document.getElementById('modals')` вызывается на уровне модуля при импорте — это сломает SSR и jest-тесты без jsdom.
- Дублирование: есть `enum pageUrls` и отдельные `const HOMEURL`, `REGURL` и т.д. — два источника правды для одних и тех же значений.

#### 8. Deploy-скрипты с хардкодом

В `package.json`:
```json
"deploy-script": "npm run build && scp -r ./build/* kirillchistov@62.84.123.141:/home/react-burger"
```
Персональный IP и имя пользователя зафиксированы в коде репозитория.

#### 9. Верстка и UX

По структуре папок компонентов видно, что верстка выполнена через UI-kit `@ya.praktikum/react-developer-burger-ui-components`. Это даёт базовый консистентный UI, но ограничивает кастомизацию. Отдельная страница ингредиента (`/ingredients/:id`) существует, но навигационный путь к ней из UI не очевиден.

#### 10. Доступность (a11y)

Нет явных aria-атрибутов, focus management при открытии модалок не прослеживается, закрытие по Escape — неизвестно (компонент Modal не удалось получить полностью).

## НЕДЕЛЯ 2 — Redux: миграция на RTK

### 🟠 RTK-01 · Миграция на @reduxjs/toolkit

Это самый объёмный рефакторинг месяца. Рекомендуется делать срез за срезом, не всё сразу.

| Подход | Плюсы | Минусы |
|---|---|---|
| **Полная миграция на RTK createSlice + createAsyncThunk** | Убирает 70% boilerplate, встроенный Immer, авто-типизация, RTK Query опционально | Потребует переименования экшенов, обновления всех импортов |
| **RTK + RTK Query для API** | Кэширование, дедупликация запросов, автоматический loading/error state | Нужно изучить RTK Query, больший scope изменений |
| **Оставить классический Redux** | Нет изменений в коде | Технический долг, несовместимость с современными практиками |

**Рекомендация:** RTK `createSlice` + `createAsyncThunk` без RTK Query (RTK Query — следующий шаг).

**Порядок миграции срезов:**
1. `ingredientsSlice` — простейший, хороший старт
2. `orderSlice` — средней сложности, есть DnD-логика
3. `authSlice` — самый сложный, но самый важный
4. WS-редьюсеры — оставить middleware как есть, только slice

**Ожидаемый результат:** -60% строк в `services/`, удаление папок `actions/` и `reducers/types/`

**Оценка:** 3–4 дня
